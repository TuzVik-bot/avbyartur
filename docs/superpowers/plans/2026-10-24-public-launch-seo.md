# Публичный SEO-запуск авторынок.бел — план разработки и деплоя

> Дата: 2026-10-24. Основание: SEO-аудит живого сайта и кода в этой сессии.
> Статус: в исполнении. Деплой каждой стадии — после явного одобрения пользователя.

## Цель

Сделать проект видимым для поисковиков и нейросетей: снять трёхслойный noindex
управляемым флагом, закрыть пробелы SEO-инфраструктуры и выпустить релиз на
production по действующей релизной процедуре VPS.

## Факты, на которых построен план

- Активный релиз VPS: `category-subcategories-20261024-r3`; цепочка edge:
  внешний OpenResty (TLS, HTTP→HTTPS 301) → nginx VPS
  (`docs/archive/deploy/suite-s1.denjik.by.pilot.nginx.conf`, `add_header X-Robots-Tag
  "noindex, nofollow, noarchive" always;`) → web `127.0.0.1:8080`.
- Индексация запрещена на 3 уровнях: X-Robots-Tag (next.config.ts + nginx),
  meta robots корневого layout, точечные noindex страниц. Флаг
  `AVTORINOK_PUBLIC_INDEXING_ENABLED` управляет только robots.txt/sitemap.
- На живом сайте meta robots = `index, follow` при локальном коде noindex —
  задокументированное расхождение
  (`docs/releases/2026/CATEGORY_SUBCATEGORIES_DEPLOY_2026-10-24.md`, строки 44–47).
  Новый релиз из репо делает репо источником истины.
- Каталог публично пуст (0 активных объявлений), sitemap = 7 URL; ссылки на
  `/trucks`, `/trailers`, `/buses`, `/parts` битые (категории в backend есть,
  нет только фронтовых роутов).
- Релизная процедура: candidate = копия активного релиза + точечные файлы,
  образы linux/amd64, дамп БД до переключения, flock
  `/home/suite/apps/avtorinok-web-deploy.lock`, healthz/smoke/браузерная
  приемка, отчёт в docs/runtime/, откат сохранённым образом.

## Стратегия

Два независимых переключателя:

- **Стадия A** — релиз нового кода с выключенным публичным режимом: для
  поисковиков ничего не меняется, риск нулевой.
- **Стадия B** — включение индексации: env-флаг (B1) и nginx-шаблон (B2).
  B2 меняет Nginx и по правилам проекта требует отдельного явного запроса.

## Этапы

1. **База**: baseline-коммит рабочего дерева; полный прогон проверок;
   TESTING.md как running log.
2. **SEO-код web/** (принцип: при выключенном флаге поведение дословно
   текущее; тесты на оба режима):
   - единый публичный режим: `pilot-visibility.ts`, robots layout из флага,
     description без «в закрытом пилоте», бейджи «ПРОЕКТ / ЧЕРНОВИК» по флагу;
   - `next.config.ts`: X-Robots-Tag только при выключенном флаге, images
     (avif/webp), HSTS в публичном режиме;
   - OG/Twitter: хелпер в `seo.ts`, дефолты layout, og:image объявлений =
     первое фото, брендовый og-default;
   - JSON-LD: Organization + WebSite+SearchAction (layout), BreadcrumbList
     (объявление/дилер), Article (статьи), AutoDealer (дилер);
   - sitemap: статические страницы и 5 категорийных лендингов;
   - description+canonical для статических страниц без меты;
   - лендинги `/trucks`, `/trailers`, `/buses`, `/parts` по шаблону
     motorcycles; редирект canonical карточки 307→308; оптимизация фото
     (снятие `unoptimized`);
   - верификационные мета-теги GSC/Яндекса через env;
   - nginx public-шаблон без X-Robots-Tag (в репо, применение = стадия B2).
3. **Контент** (параллельно, отдельные гейты): импорт onliner.by через
   очередь модерации — только по отдельному явному запросу; запуск возможен
   и без него.
4. **Деплой**: свежая SSH-проверка; стадия A по релизной процедуре
   (дамп, preflight, flock, healthz, браузерная приемка, отчёт); стадия B1 —
   env `AVTORINOK_PUBLIC_INDEXING_ENABLED=true`; стадия B2 — nginx public
   шаблон (`nginx -t` → reload) — только после явного OK пользователя.
5. **Панели**: регистрация GSC/Яндекс.Вебмастер/Bing пользователем
   (верификация мета-тегом через env), отправка sitemap, мониторинг индексации.

## Ограничения

Тома `avtorinok_postgres`/`avtorinok_private_media` не трогать, никогда
`down -v`; `.env` не читать (только hash/права); синтетику не публиковать;
push в GitHub и nginx-изменения — только по явному одобрению; откат каждой
стадии — сохранённым образом / env off / прежний nginx шаблон.
