При объединении с автомобильным каталогом географические записи остаются в `regions`, а происхождение их снимка хранится отдельно в `geography_source`. Обновление Wikidata-каталога сохраняет оба поля независимо от метаданных источника марок и моделей.

## Покрытие

В seed 7 региональных вариантов и 12 городских записей. В него входят все 6 областей, все 6 областных центров, Минск как отдельный региональный вариант и 6 дополнительных районных центров: Пинск, Орша, Мозырь, Лида, Борисов и Слуцк. QID каждой записи содержится в JSON.

Областные центры имеют прямой `P131` на соответствующую область. У дополнительных городов проверен путь `P131+` до области; их непосредственные родители — районы: Орша — Оршанский район `Q1245303`, Мозырь — Мозырский район `Q1952838`, Лида — Лидский район `Q1953388`, Борисов — Борисовский район `Q2092836`, Слуцк — Слуцкий район `Q2091666`. Пинск имеет прямой `P131` на Брестскую область. В seed районы не моделируются, поэтому эти города сгруппированы по подтверждённой области-предку.

Минск (`Q2280`) в Wikidata одновременно описан как город и административная единица первого уровня; его `P131` указывает на Беларусь (`Q184`). Seed использует `Q2280` и для отдельного регионального выбора, и для вложенной записи города, чтобы соответствовать текущей схеме `regions[].cities[]`. Это адаптация структуры приложения, а не утверждение, что у города Минска есть `P131` на самого себя.

Набор неполный: он не содержит полного списка районных центров, городов, посёлков и деревень Беларуси, районов как отдельных сущностей, альтернативных названий или ручной проверки муниципальных границ. Отсутствие населённого пункта в файле не означает, что его нет. Wikidata поддерживается сообществом; связи и подписи могут меняться или содержать ошибки. Повторный импорт требует повторной проверки связей и покрытия.

## Проверка запроса

Верификационный запрос проверял страну `Q184`, тип областей Беларуси `Q209325`, русские подписи, допустимые типы городов `Q1549591`, `Q79323854`, `Q79324274`, `Q7930989`, `Q902814`, непосредственный `P131` и цепочку `P131+` до области. Для Минска отдельно проверялось совпадение сущности регионального и городского варианта (`Q2280`), тип города `Q7930989` и тип административной единицы первого уровня `Q10864048`.

```sparql
SELECT DISTINCT ?region ?regionLabel ?regionType ?regionTypeLabel ?city ?cityLabel ?cityType ?cityTypeLabel ?directParent ?directParentLabel WHERE {
  VALUES (?region ?city) {
    (wd:Q173822 wd:Q140147)
    (wd:Q173822 wd:Q204150)
    (wd:Q185700 wd:Q102217)
    (wd:Q185700 wd:Q208609)
    (wd:Q188732 wd:Q2678)
    (wd:Q188732 wd:Q386487)
    (wd:Q189822 wd:Q154835)
    (wd:Q191061 wd:Q181376)
    (wd:Q191061 wd:Q241475)
    (wd:Q192959 wd:Q19313)
    (wd:Q192959 wd:Q201243)
    (wd:Q2280 wd:Q2280)
  }
  VALUES ?cityType {
    wd:Q1549591
    wd:Q79323854
    wd:Q79324274
    wd:Q7930989
    wd:Q902814
  }
  ?region wdt:P17 wd:Q184;
          rdfs:label ?regionLabel;
          wdt:P31 ?regionType.
  ?city wdt:P17 wd:Q184;
        rdfs:label ?cityLabel;
        wdt:P31 ?cityType.
  FILTER (LANG(?regionLabel) = "ru" && LANG(?cityLabel) = "ru")
  OPTIONAL { ?city wdt:P131 ?directParent. }
  {
    ?region wdt:P31 wd:Q209325.
    ?city wdt:P131+ ?region.
  }
  UNION
  {
    FILTER (?region = wd:Q2280 && ?city = wd:Q2280)
    ?region wdt:P31 wd:Q10864048.
    ?city wdt:P31 wd:Q7930989.
  }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "ru,en". }
}
ORDER BY ?region ?city ?cityType
```

Весь импортный JSON имеет `schema_version: 1`; `makes` и `body_types` оставлены пустыми, чтобы файл соответствовал локальному формату импорта. При добавлении новых записей нужно заново проверить QID, класс и родительские связи и обновить дату, контрольную сумму и это описание покрытия.
