# Catalog Source and Coverage

`data/catalog.json` combines a CC0 Wikidata snapshot with a small number of manually curated model records. The top-level `source` block describes only the Wikidata snapshot and records its retrieval time, reuse terms, endpoint, and SHA-256 of the catalog query assembled by `scripts/refresh_wikidata_catalog.py`. Wikidata models enter that snapshot only when they have a direct P1716 (`brand`) relation to the selected make QID and are an instance or subclass of `Q3231690` (`car model`). The query does not use manufacturer property P176 to assign a model to a brand because P176 can point to a parent company.

Wikidata's structured data is offered under CC0 1.0: [Wikidata reuse terms](https://www.wikidata.org/wiki/Wikidata:Reuse). The seed contains no Wikimedia images. A Wikidata QID and statement provide traceable provenance, but do not independently establish a manufacturer's current lineup or validate every community-maintained statement. Manual records carry a per-record `source.url` for the fact they document. The CC0 statement does not apply to those external sources, and this project makes no claim about their reuse terms.

## Refresh and Import

The refresh script uses only Python's standard library. It defaults to a dry run and validates records before any write:

```sh
python3 scripts/refresh_wikidata_catalog.py
python3 scripts/refresh_wikidata_catalog.py --write
```

`--write` atomically replaces `data/catalog.json` and `data/catalog-coverage.json`. Use `--max-models-per-make N` to change the deterministic subset size; matching control models are selected first, then remaining labels sort alphabetically. Existing non-Wikidata makes and models, Wikidata models with saved generations, manual body types, body variants, and regions are preserved. Wikidata body types refresh by QID, so new labels and IDs can be added without dropping manual records. Other Wikidata models outside the new selection can be dropped. Any row whose per-record `source.name` is not `Wikidata` is treated as a sourced/manual addition and wins on an ID collision. When a control has no QID, refresh carries forward its prior `matching_model_slug` if the same requested control still exists and that slug resolves in the merged catalog, then recalculates generation and body-variant counts through that model. Removing or renaming the manual model intentionally breaks this association. The API importer separately preserves manually edited database rows.

For a model QID present in both snapshots, refresh carries forward generation rows omitted by the new result. If a Wikidata generation refreshes, matching body variants refresh by QID or slug, non-Wikidata variant records take precedence, and previously stored variants omitted from the new row remain. A model or generation whose source is not Wikidata keeps its full record. This refresh emits no generation statements itself, so it preserves separately sourced generation and body-variant data without claiming new coverage.

Compose mounts `data/` read-only at `/app/data`. With the API running, inspect and apply through the backend's validating importer:

```sh
./scripts/import-catalog.sh --dry-run
./scripts/import-catalog.sh --apply
```

The importer validates the entire version-1 catalog before writing, keys source rows by Wikidata QID, stores the dataset source/license/checksum, and does not delete rows omitted from this partial seed. It does not silently change database state when the catalog JSON is refreshed.
