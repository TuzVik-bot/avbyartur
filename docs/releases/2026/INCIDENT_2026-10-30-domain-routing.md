# Ошибочная маршрутизация авторынок.бел — 30 октября 2026

## Результат

В 14:03–14:04 по Минску публичный HTTPS снова отдаёт «Авторынок»:
`<title>Автомобили Беларуси</title>`, HTTP 200, без AURUM.
У домена теперь отдельная конфигурация Nginx. Соседний AURUM сохранён.

## Что произошло

- DNS основного домена указывал на ожидаемый IP `178.124.211.251`; AAAA не обнаружен.
- До исправления в `sites-enabled` был только `suite-s1.denjik.by`.
  Его `server_name` содержал только `suite-s1.denjik.by`; отдельной привязки
  `xn--80aeylebmo7f.xn--90ais` не было. Домен попадал в этот общий vhost.
- Файл `/etc/nginx/sites-available/suite-s1.denjik.by` изменён 30 октября
  в 08:07 UTC (11:07 по Минску): вместо reverse proxy появился статический
  `root /var/www/suite-s1.denjik.by` для AURUM Detailing.
- Публичная страница до исправления называлась «AURUM — детейлинг-студия
  в Минске | Полировка, керамика, оклейка, русификация Geely».
- Предыдущий прокси сохранился рядом как `suite-s1.denjik.by.proxy-bak`.
  Само приложение «Авторынок» продолжало работать на `127.0.0.1:8080`;
  все пять контейнеров были healthy.

Это подтверждает ошибку размещения двух сайтов на одном vhost.
Кто именно заменил конфигурацию и какой командой, этим расследованием
не установлено. Доказательств перехвата DNS не обнаружено.

## Исправление

После явного разрешения пользователя:

1. Сохранены исходный vhost AURUM, предыдущий прокси, путь активного выпуска
   и права `.env` в
   `/home/suite/backups/avtorinok/domain-routing-20261030T1103Z/`.
2. Из рабочего прокси создан `/etc/nginx/sites-available/avtorinok-domain`.
   В `server_name` явно указаны `xn--80aeylebmo7f.xn--90ais` и
   `www.xn--80aeylebmo7f.xn--90ais`; upstream — `127.0.0.1:8080`.
3. Создана ссылка `/etc/nginx/sites-enabled/avtorinok-domain`.
4. `nginx -t` прошёл; выполнена мягкая перезагрузка Nginx.
   Конфигурация AURUM осталась прежней.

Первый reload из стандартного профиля служебного контейнера не смог отправить
сигнал процессу Nginx. Повторный reload с разрешением этого сигнала завершился
успешно; публичная проверка выполнена после него.

Активный выпуск остался
`/home/suite/apps/releases/catalog-gallery-skoda-plan-20261028-r1-KwUuoM`.
Контейнеры приложения не пересоздавались, миграции и импорт не запускались.
`.env` имеет права 600; тома `avtorinok_postgres` и
`avtorinok_private_media` сохранены. Режим индексации не менялся.

## Проверки

- Публичная главная по HTTPS: 200, правильный заголовок, AURUM отсутствует.
- `/api/v1/auth/capabilities`: JSON с `email_registration=true`;
  `/login?next=%2Fsell`: страница «Вход — Авторынок BY».
- `/healthz`: 200 с телом `ok`.
- HTTP основного домена: 301 на HTTPS того же домена.
- `Host: suite-s1.denjik.by` на VPS продолжает отдавать статический AURUM.
- API, web, worker, db и test-mail после исправления healthy.
- `www` пока не резолвится; его имя предусмотрено в Nginx, но публичная
  доступность этого варианта не подтверждена и DNS не менялся.
- Браузерная проверка недоступна: локальный браузер выключен в настройках Work.
  Этот инцидент не является web-релизом и не подтверждает полный сценарий регистрации.
- Проверка секретов всего локального дерева нашла 117 срабатываний, в том числе
  в игнорируемых `.env` и старых `.superpowers/` артефактах; это не успешная
  проверка всего проекта. Содержимое секретов не выводилось. На пяти файлах этого
  исправления срабатываний нет; зависимости не менялись,
  онлайн-проверка зависимостей не выполнялась.

## Защита от повторения

- Использовать отдельный файл `avtorinok-domain` и его явные домены.
  Замена соседнего `suite-s1.denjik.by` больше не должна менять выбор vhost
  для `авторынок.бел`.
- Сверять изменения с `deploy/avtorinok-domain.nginx.conf`; не публиковать
  «Авторынок» через соседний статический web-root или исторические шаблоны.
- До и после разрешённых изменений проверять имя сайта в HTML и JSON
  `/api/v1/auth/capabilities`, а не только HTTP 200.
- Не добавлять домен «Авторынка» в другой vhost; всегда проверять полный
  вывод `nginx -t`, включая предупреждения о конфликтующих именах.
- Для защиты от произвольных изменений администратором нужны отдельные
  права развёртывания или отдельный сервер. Это дополнительная мера;
  в данном восстановлении права доступа и серверная архитектура не менялись.

### Дополнение: независимый `/healthz`, 14:21 по Минску

После отдельного явного разрешения пользователя историческая зависимость
`/healthz` от `/var/www/suite-s1.denjik.by/healthz.txt` удалена.
Вместо файлового `alias` Nginx самостоятельно возвращает `200`,
`Content-Type: text/plain` и тело `ok` с переводом строки.
Это проверка доступности Nginx; готовность приложения по-прежнему проверяют
Docker healthchecks.

Перед изменением конфигурация сохранена как
`/home/suite/backups/avtorinok/domain-routing-20261030T1103Z/avtorinok-domain.before-health-isolation-20261030T1121Z.conf`.
`nginx -t` прошёл; мягкая перезагрузка успешна. По публичному HTTPS проверены
точное тело `/healthz`, главная «Автомобили Беларуси» и JSON auth capabilities
с `email_registration=true`; все пять контейнеров healthy.
Копия `deploy/avtorinok-domain.nginx.conf` совпадает с серверной по SHA-256:
`f9dde4fd51831a95c85881ca394ad1ed29b4750c857bb0af7f8842d8b9f47802`.

## Откат маршрутизации

Для возврата состояния до исправления убрать только ссылку
`/etc/nginx/sites-enabled/avtorinok-domain`, проверить `nginx -t` и мягко
перезагрузить Nginx. Это снова направит домен на AURUM и допустимо только
по отдельному решению. Файлы приложения и данные при таком откате не меняются.
