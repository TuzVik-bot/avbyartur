# Таможенный калькулятор — результат разработки 2026-10-04

## Реализовано
Страница `/customs-calculator`, ссылки в шапке и разделе «Разделы» подвала. Форма цены/валюты/точной даты выпуска/типа ДВС/объема/подтверждений. Серверный расчет физлица M1 для личного пользования из-за пределов ЕАЭС в Беларусь, без льгот; EV/гибриды/ЕАЭС/юрлица исключены. Покупная цена не включается в итог платежей.

Пошлина, утильсбор, сбор за операции и итог BYN раздельно; дата расчета/курса, версия норм, ссылки и пояснение об окончательном курсе на день регистрации пассажирской декларации. Все значения исходных данных редактируются вручную; год справочника не подменяет точную дату выпуска.

Backend использует Decimal/HALF_UP, календарные годовщины, версионируемый JSON с источниками и датами действия. НБРБ: сегодняшний снимок Europe/Minsk, кратность валют, таймаут/ограничение размера/кэш успешного снимка; старые и выдуманные курсы не подставляются. Результат формы сбрасывается при редактировании; поздние ответы от старого запроса игнорируются. Same-origin HTTP credentials сохраняют внешний Basic Auth; аккаунт и CSRF-bootstrap для расчета не нужны.

Контрольный gate привязан к версии тарифа, хэшу корпуса и каждому из 24 реально наблюденных входов/выходов ГТК. Runtime перерасчитывает их; перенос одного примера под другие ID не проходит. Нормы и случаи находятся внутри backend/app/data и включаются существующим Dockerfile. Хэш внешнего audit Markdown хранится как provenance и не перепроверяется по байтам на сервере; хэш корпуса случаев перепроверяется.

## Пределы результата
На VPS не развернуто. Production данные, тома, Nginx/Basic Auth/noindex не менялись. Проверка Basic Auth состояла в сохранении same-origincredentials и existing конфигурации; remoteпилот и браузер через настоящуюVPSBasicAuth в этой задаче не проверялись. Правовые обновления требуют проверки первичных источников, новой версии норм и повторной сверки; автоматического изменения юридических ставок нет. Сверка ГТК проверяет тарифные группы/суммы, а не точные календарные даты, утильсбор или общую импортную стоимость.

## Итог обзоров и решения
Backend и frontend проверены независимыми агентами GPT-6 Luna max. Два важных замечания исправлены (граница цены и ID→input coverage); повторные scoped обзоры чистые. Итоговый обзор всей функции APPROVE, новых важных замечаний нет.

Принятые решения и цена ошибочного выбора:
- Начать разработку без повторного согласования: пользователь прямо поручил план и запуск; ошибочное понимание требует пересмотра обратимых локальных изменений.
- Одно managed worktree, сначала последовательное исполнение, затем параллельные disjoint зоны после установления API: исключает смешивание main и уменьшает конфликт; ошибка приводит к повторной генерации типов/исправлению API стыка.
- Расширить backend ownership на точный тест маршрутов: новые endpoints требуют обновления inventory; ошибка исправляется корректировкой expectations.
- ГТК сверяет тарифные группы, календарные годовщины — отдельные тесты: official form принимает группу; ошибка возрастной семантики требует дополнительной юридической сверки.
- Runtime evidence хранится в app/data: Docker копирует app; ошибка упаковки потребовала бы коррекции пути/образа.
- Audit Markdown SHA остается provenance, а runtime сверяет fingerprint правил, actual cases hash/input tuples/formula: ошибка потребовала бы включения audit bytes в образ и проверки их digest.

Финальная ветка codex/customs-calculator; код готов к отдельной задаче релиза после свежей проверки production доступа/rollback/актуальности норм. В этой задаче деплой не выполнялся.
